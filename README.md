# Трекер обращений и отвлечений

Личное веб-приложение для одного пользователя на компьютере и телефоне. Нажатие «Отвлекли» фиксирует начало обращения, «Завершить» — окончание. Источник, тип, заметку и причину участия можно уточнить позже. Есть ручной ввод прошедших обращений, журнал, числовая сводка и необязательный разбор через языковую модель.

**Статус: начальная версия.** Приложение собирается, локальные автоматические проверки проходят, но весь объём [спецификации 1.3](docs/product-plan-1.3.md) ещё не реализован и не прошёл приёмку. Известные ограничения перечислены ниже. Реальный деплой в Cloudflare и проверка на телефоне не выполнялись.

## Что нужно для запуска

| Компонент | Для чего нужен | Обязателен |
| --- | --- | --- |
| Аккаунт Cloudflare и Worker | Интерфейс и API по одному HTTPS-адресу | Да |
| База Cloudflare D1 | Общий журнал для всех устройств | Да |
| Cloudflare Zero Trust / Access | Вход только для email владельца | Да |
| Node.js 24 и npm | Установка зависимостей и публикация через Wrangler | Да для команд из инструкции |
| Python 3 | Автоматические SQL-тесты | Для полной проверки перед публикацией |
| Собственный домен | Удобное имя приложения | Нет, можно использовать `workers.dev` |
| API-ключ OpenRouter или совместимого поставщика | Текстовый разбор дня и недели | Нет |

Здесь нет отдельного сервера, Docker, PostgreSQL или Cloudflare Tunnel. Один Worker обслуживает статические файлы и API, одна D1 хранит данные. GitHub хранит исходники; отправка коммита сама по себе не развёртывает приложение.

### Что означает API-ключ LLM и за что платить

API-ключ — секрет для обращения к поставщику модели от имени владельца. **Сам ключ не является отдельной платной лицензией.** Условия оплаты зависят от поставщика и модели: платные вызовы обычно тарифицируются по входным и выходным токенам; у некоторых моделей есть бесплатные варианты с ограничениями.

В приложении основной поставщик — OpenRouter, также поддержан совместимый Chat Completions API. Подписка ChatGPT сама по себе не предоставляет ключ и оплаченные вызовы OpenRouter или другого API.

Без ключа работают таймер, журнал, ручные записи, статистика и экспорт. Кнопки разбора и проверки модели обращаются к внешнему API; проверка модели тоже может стоить денег. При неизвестном исходе запроса нельзя гарантировать отсутствие списания. Один `report_id` не отправляется к модели повторно автоматически; новый запуск — отдельное действие пользователя.

Ключ хранится в Worker Secret `LLM_API_KEY`, не в Git, настройках браузера или тексте README. Настройки позволяют увидеть только признак наличия ключа. Разбор отправляет поставщику снимок записей, включая заметки; перед подключением выбирайте поставщика, которому готовы передавать эти данные.

Плата за LLM и плата за инфраструктуру Cloudflare — разные вещи. Для личного использования могут подойти бесплатные квоты Workers, D1 и Access; актуальные ограничения и условия нужно сверять с [тарифами Workers](https://developers.cloudflare.com/workers/platform/pricing/), [D1](https://developers.cloudflare.com/d1/platform/pricing/) и [Zero Trust](https://www.cloudflare.com/plans/zero-trust-services/). Фиксированная бесплатность не гарантируется.

## Развёртывание на Cloudflare Workers

Полная инструкция с командами, настройкой Access, проверкой входа, обновлением и резервным копированием: **[Развёртывание и обслуживание](docs/cloudflare-deployment.md)**.

Порядок для новой установки:

1. Склонировать репозиторий, выполнить `npm ci`, `npm test` и `npm run check`.
2. Войти в Cloudflare через `npx wrangler login`, создать новую D1.
3. Скопировать [шаблон конфигурации](wrangler.production.example.jsonc) в `wrangler.production.jsonc`, заполнить ID базы и применить миграции к новой базе.
4. Выполнить первоначальный деплой без параметров Access: API останется закрыт с `503 AUTH_CONFIGURATION_ERROR`; доступна только оболочка интерфейса без личных данных.
5. В Cloudflare Access защитить **весь Worker / All traffic** политикой для точного email владельца. Затем указать `ACCESS_TEAM_DOMAIN`, `ACCESS_AUD` и `ACCESS_EMAIL` в локальной конфигурации и повторить деплой.
6. Проверить вход владельца, отказ другому пользователю и доступность одной записи с двух устройств. Только после этого использовать личные данные.
7. При необходимости добавить `LLM_API_KEY` через Worker Secrets и выбрать модель в приложении.

`wrangler.production.jsonc` не отслеживается Git. Все команды публикации и обслуживания должны явно использовать `--config wrangler.production.jsonc`; команды без этого флага читают исходный `wrangler.jsonc` с заглушкой ID базы.

### Обязательные параметры

| Параметр | Где задаётся | Пример / источник |
| --- | --- | --- |
| `name` | Конфигурация Wrangler | `interruption-tracker` |
| `d1_databases[].binding` | Конфигурация Wrangler | Строго `DB` — это имя использует код |
| `database_id` | Конфигурация Wrangler | UUID из `wrangler d1 create` |
| `ACCESS_TEAM_DOMAIN` | `vars` в локальной конфигурации | `https://your-team.cloudflareaccess.com`, не адрес Worker |
| `ACCESS_AUD` | Там же | Application Audience (AUD) созданного Access-приложения |
| `ACCESS_EMAIL` | Там же | Точный email владельца, разрешённый политикой Access |
| `LLM_API_KEY` | Worker Secret | Необязательный ключ выбранного поставщика |

API дополнительно проверяет подпись Access JWT, issuer, audience, срок действия и email. Проверка API **не закрывает статические файлы**: Access должен защищать приложение целиком. В шаблоне отключены Version URLs (`preview_urls: false`); отдельные окружения и новые preview-развёртывания требуют своей защиты и своей базы.

## Локальная разработка

Команды выполняются из корня репозитория:

```sh
git clone https://github.com/HyperDodo/distractions-tracker.git
cd distractions-tracker
npm ci
npm run migrate:local
npm test
npm run check
npm run dev
```

- `migrate:local` создаёт/обновляет только локальную D1 в `.wrangler/`.
- `test` запускает JavaScript-тесты и Python-проверки SQLite. Используются тестовые ключи и подмена внешнего LLM, реальные платные вызовы не выполняются.
- `check` собирает Worker и Static Assets через `wrangler deploy --dry-run`, без загрузки в Cloudflare.
- `dev` запускает локальный Worker с интерфейсом. **API без корректного подписанного Access JWT закрыт.** Полноценный локальный вход и разрешающий обход авторизации не реализованы. Простое заполнение `.dev.vars` не создаёт JWT.

Для проверки сценариев в настоящем браузере используйте отдельный закрытый тестовый Worker и отдельную D1; не подключайте production-базу к разработке. Автоматические API-тесты проверяют обработчики с SQLite-адаптером и настоящей подписью тестового JWT; это не проверка сервиса Cloudflare Access или удалённой D1.

В ограниченной облачной среде с недоступным `~/.config` Wrangler можно запускать с `XDG_CONFIG_HOME=/tmp/interruption-xdg`; для npm — с `--cache /tmp/interruption-npm-cache`. На обычном компьютере эти переопределения обычно не нужны.

## Устройство проекта

```text
backend/
  worker.js       Маршрутизация, настройки, дневной снимок и контекст дня
  entries.js      Создание, изменение, завершение и переключение обращений
  auth.js         Проверка Access JWT, Origin и JSON
  calendar.js     Границы дней/недель и числовая статистика
  reports.js      Резервация попытки, вызов LLM и хранение отчёта
  export.js       Постраничная выгрузка JSON/CSV
frontend/public/
  index.html, styles.css, manifest.webmanifest
  js/app.js       Экраны и действия пользователя
  js/api.js       HTTP-запросы и обработка ошибок доступа
  js/store.js     Последовательное сохранение и черновик операции
  js/time.js      Отображение и оценка времени сервера
migrations/       Версионированные миграции D1
tests/            Тесты API, JWT, календаря, сохранения, отчётов и SQL
docs/             Спецификация и инструкция развёртывания
```

Static Assets обслуживают интерфейс, `/api/*` обрабатывает Worker до SPA fallback. Неизвестный API-путь возвращает JSON. В D1 четыре таблицы: `settings`, `entries`, `day_notes`, `reports`. Уникальный индекс запрещает две активные записи. Текст модели отображается как текст; модель не получает инструментов изменения журнала.

## Что проверено и что осталось

Локально прошли 12 JavaScript-тестов и 5 SQL-тестов, сборка Worker, миграции локальной D1 и запуск интерфейса. Проверяются, в частности, подпись Access JWT, конфликт редакций, границы DST, строгие пересечения, последовательное сохранение быстрых действий, восстановление create/switch, одна попытка LLM и экспорт более одной страницы с нейтрализацией формул CSV.

Эти проверки не заменяют приёмку реальных Cloudflare D1 и Access, двух устройств, iPhone, плохой сети и настоящего поставщика LLM.

Известные функциональные пробелы относительно плана 1.3:

- Ручной ввод времени работает только при совпадении часового пояса устройства и настройки; неоднозначное время при смене UTC-смещения отклоняется, выбора смещения нет.
- Нет полного сравнения и разрешения конфликтов по полям, сохранения всех ручных форм при обрыве связи и восстановления неизвестного результата для всех команд.
- Не реализованы ручное окончание забытого таймера, полная детализация статистики, пагинация и удаление отчётов в интерфейсе, признаки свежести отчёта.
- Последние источники выбираются из 100 последних записей.
- Полноценный локальный вход, браузерные E2E и проверка iPhone отсутствуют.

Экспорт JSON/CSV читает данные страницами и не является атомарной резервной копией базы. Для обслуживания используйте штатный экспорт D1 и проверяйте резервные копии. Публикация исправлений не должна пересоздавать базу: применяются только новые миграции, уже применённые SQL-файлы не редактируются.
